Orthanc, Tailscale & Multi-Hospital Setup

Deployment reference for https://pacsd.onrender.com

1. Does Tailscale need to be installed on the client system?

Yes, but only on one computer at the hospital: the PC that runs Orthanc. Nothing has to be installed on the scanners, the radiologists' computers or Render.

Scanners (CT / MR / X-ray)→ DICOM 4242 (local network) → Orthanc PC + Tailscale→ HTTPS (Funnel) → pacsd.onrender.com→ Radiologists (any browser)
ComputerInstall Tailscale?
Hospital Orthanc PCYes
Scanners / modalitiesNo. They send to the Orthanc PC on the local network.
Radiologist / doctor computersNo. They just open https://pacsd.onrender.com.
Render (cloud)No. It reaches Orthanc through the public Funnel address.

Steps on the hospital Orthanc PC

  1. Download and install Tailscale for Windows from tailscale.com/download/windows.
  2. Sign in with the GMS (Galactic) account, not a hospital staff account, so that you control every site from one place.
  3. In the Tailscale tray icon menu, enable Run unattended. This keeps it running after a reboot or when nobody is logged in.
  4. In the Tailscale admin console under Machines, open this PC's menu and choose Disable key expiry. Otherwise the connection stops after about 180 days.
  5. Under DNS in the admin console, enable MagicDNS and HTTPS Certificates.
  6. In PowerShell as Administrator, run: 
    tailscale funnel --bg 8042
    The first time, it shows a link to approve Funnel. Approve it and run the command again.
  7. Copy the address it prints, for example https://gh-orthanc.tail9f8e7.ts.net, and put it in Render as ORTHANC_URL, together with ORTHANC_USERNAME and ORTHANC_PASSWORD.
PC requirements: on 24/7, sleep turned off, a fixed local IP (for example 192.168.1.50), and ideally on a UPS.
If the hospital IT team does not allow Tailscale: use Cloudflare Tunnel (same idea, different tool), or ask them to forward port 8042 to the Orthanc PC with HTTPS. Tailscale is the simplest option.

2. What happens when there are more hospitals?

Right now PACSD can connect to only one Orthanc: there is a single ORTHANC_URL setting on Render, used everywhere in the server code. The same steps work for the first hospital, but a second hospital with its own Orthanc PC can't be added just by repeating them.

Option 1: One Orthanc per hospital, all connected to PACSD (recommended, needs a code change)

Hospital 1: Scanners → Orthanc + Tailscale Hospital 2: Scanners → Orthanc + Tailscale Hospital 3: Scanners → Orthanc + Tailscale
→ pacsd.onrender.com
  • Every hospital gets the same on-site setup as the first: one PC with Orthanc and Tailscale, and scanners sending over the local network.
  • In PACSD, each facility gets its own Orthanc connection (address, username, password) under Facility settings, instead of one global ORTHANC_URL.
  • Studies are automatically filed under the right hospital, because PACSD knows which Orthanc they came from. No AE-title guesswork.
  • Adding hospital number 10 is just: install the PC on site, then paste its address into PACSD. No Render changes or redeploys.
  • One hospital's PC being offline doesn't affect the others.

What would change in PACSD: store Orthanc connections per facility in the database, make the 10-second sync check each hospital's Orthanc, remember which Orthanc every image came from (so the viewer and previews fetch from the right place), and add an "Orthanc gateway" form with a Test connection button on the admin screen.

Option 2: One central Orthanc in the cloud (no code change, but worse for hospitals)

Rent a cloud server and run a single Orthanc there. Every hospital's scanners, or a small local Orthanc at each site, forward images over the internet to it.

Downsides:

  • Scanners sending DICOM directly over the internet is unencrypted, and many hospital IT teams will refuse it.
  • If a hospital's internet drops, its scans aren't received.
  • When images are forwarded, the sender's AE title is lost, so PACSD can't tell which hospital they came from without extra rules.
  • You'd pay for the cloud server and its storage.

Recommendation

For the first hospital (GH): continue exactly as planned. The single-Orthanc setup works, and nothing set up now is wasted.

Before the second hospital: build Option 1. That hospital's on-site steps are then identical: install Orthanc, install Tailscale, run Funnel. The only difference is that you enter its address in PACSD's admin screen instead of Render.
