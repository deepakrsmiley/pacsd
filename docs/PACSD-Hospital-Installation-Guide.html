Hospital Installation Guide

Connecting Orthanc, Tailscale and the GE CT scanner to https://pacsd.onrender.com

How the system fits together

GE CT console→ DICOM, port 4242 (hospital LAN) → Orthanc PC + Tailscale→ HTTPS + password (Funnel) → pacsd.onrender.com→ Worklist / Viewer

PACSD on Render checks Orthanc every 10 seconds through the Tailscale address and imports any new images. Test the whole chain from your own PC first (Parts A to E). Then repeat the setup on a PC at the hospital and point the scanners at it (Part F). No scanner is needed for testing, because you can upload a DICOM file into Orthanc yourself.

Part A: Prepare PACSD (5 minutes)

  1. Sign in at https://pacsd.onrender.com. Go to Users and Roles and create at least one facility (hospital). Without a facility, incoming images are rejected.
  2. Make sure PUBLIC_BASE_URL and WEB_ORIGIN in Render are set to https://pacsd.onrender.com.

Part B: Install Orthanc on the Windows PC

  1. Download the Windows 64-bit installer from orthanc.uclouvain.be/downloads, install it with default options, and choose to run it as a service.
  2. Open Notepad as Administrator and open C:\Program Files\Orthanc Server\Configuration\orthanc.json.
  3. Find and change these lines. They already exist; just edit the values: 
    "Name" : "GMS PACS",
"DicomAet" : "GMSPACS",
"DicomPort" : 4242,
"RemoteAccessAllowed" : true,
"AuthenticationEnabled" : true,
"RegisteredUsers" : {
  "pacsd" : "Use-A-Long-Orthanc-Password-2026"
},
    Pick your own password. Save the file.
  4. Press Win + R, type services.msc, find Orthanc, and click Restart.
  5. Open http://localhost:8042 in a browser and sign in as pacsd with your password. The Orthanc Explorer page should appear.
  6. Open the DICOM port to the local network. In PowerShell as Administrator: 
    New-NetFirewallRule -DisplayName "Orthanc DICOM 4242" -Direction Inbound -Protocol TCP -LocalPort 4242 -Action Allow -Profile Private,Domain

How to confirm Orthanc's AE title, port and IP

  • Open http://localhost:8042/system and sign in as pacsd. It shows: 
    "DicomAet" : "GMSPACS",
"DicomPort" : 4242,
"Name" : "GMS PACS"
    DicomAet is the AE title you type on the CT. If it shows ORTHANC (the default), your edit to orthanc.json was not saved or the service was not restarted.
  • IP address: open Command Prompt and run ipconfig. Use the IPv4 Address of the hospital network adapter (for example 192.168.1.50), not the Tailscale adapter (100.x.x.x).

Part C: Give Render a secure path to Orthanc (Tailscale Funnel)

Which account to use for Tailscale

Use one company account owned by Galactic Medical Systems for every hospital, for example a dedicated Google or Microsoft account such as gms.pacs@gmail.com or your company Microsoft 365 account. Keep this login with GMS.

  • Do not sign in with a hospital employee's personal account. If that person leaves, you lose access and the connection.
  • Do not use your personal account either. Use a company account that can be handed over.
  • All hospital Orthanc PCs join the same Tailscale network (tailnet), so you manage every site from one admin console.
  • Turn on two-step verification for this account.

Install Tailscale only on the Orthanc PC. The CT scanner, the doctors' computers and Render do not need it.

Steps

  1. Install Tailscale for Windows from tailscale.com/download/windows and sign in with the GMS company account described above.
  2. Click the Tailscale icon in the taskbar tray and enable Run unattended (under Preferences). This keeps it running after a reboot or when nobody is logged in.
  3. Open the Tailscale admin console at login.tailscale.com/admin:
    • Under Machines, open this PC's ... menu and choose Disable key expiry. Otherwise the connection stops after about 180 days.
    • In the same menu, choose Edit machine name and give it a clear name, for example gh-orthanc. The public address becomes https://gh-orthanc.<your-tailnet>.ts.net.
    • Under DNS, enable MagicDNS and HTTPS Certificates.
  4. In PowerShell as Administrator, run: 
    tailscale funnel --bg 8042
    The first time, it prints a link to approve Funnel for this PC. Open it, approve, then run the command again.
  5. It prints your public address, for example: 
    https://gh-orthanc.tail9f8e7.ts.net
    You can show it again later with tailscale funnel status.
  6. Test it from your phone on mobile data: open that address. It should ask for a username and password; sign in as pacsd. If Orthanc Explorer loads, the tunnel works.

Part D: Connect Render to Orthanc

  1. In Render, open pacsd, go to Environment, and add:
    KeyValue
    ORTHANC_URLhttps://gh-orthanc.tail9f8e7.ts.net (your address, no slash at the end)
    ORTHANC_USERNAMEpacsd
    ORTHANC_PASSWORDUse-A-Long-Orthanc-Password-2026 (the password from Part B)
  2. Click Save and wait for the redeploy to show Live.
  3. Check the Render Logs. You should not see Orthanc sync failed. In PACSD, open Integrations or System Health; Orthanc should show as reachable.

Part E: Test without a scanner

  1. Get any sample DICOM file (.dcm). Free samples are available online, or use a CD from any scan.
  2. In Orthanc Explorer (http://localhost:8042), click Upload, drag the file in, and click Start the upload.
  3. Wait about 10 to 20 seconds, then open PACSD's Imaging Worklist. The study should appear as Unassigned under your first facility.
  4. Assign it to a radiologist and open it in the Viewer.
If this works, the cloud connection is done. Everything after this is hospital setup.

Part F: At the hospital (real scanners)

  1. Repeat Part B and Part C on a hospital PC with these requirements:
    • On 24/7. Turn sleep off in PowerShell as Administrator: 
      powercfg /change standby-timeout-ac 0
powercfg /change hibernate-timeout-ac 0
    • A fixed local IP, for example 192.168.1.50. Ask the hospital IT team for a DHCP reservation or a static IP. If the IP changes, the CT can no longer send.
    • Ideally on a UPS, and on the same network as the CT scanner.
  2. Update ORTHANC_URL in Render to this PC's Tailscale address and wait for the redeploy.
  3. Configure the GE CT (Part G) and register it in PACSD (Part H).
  4. Press Echo / Verify on the scanner. It should succeed. Then send one test study and check that it appears in the Worklist.

Part G: GE CT console configuration

The CT needs to know where to send images: Orthanc's AE title, IP and port. Have the details from Part B ready (AE title from /system, IP from ipconfig).

Steps on the GE CT console

Menu names vary between GE models (Revolution, Optima, BrightSpeed, Discovery). The network configuration screen is often protected by a service password, so do this with the hospital's CT technologist or GE field engineer.

  1. On the CT console, open the Network / DICOM configuration screen. On many GE consoles this is under Utilities / Tools → Network Configuration → Remote Hosts, or in the Browser/Patient List as Network → Remote Hosts.
  2. While you're on this screen, note the CT's own AE title, shown as Local / Host AE Title (for example GECT_GH1). You need it in Part H.
  3. Click Add (new remote host) and enter the values from the table above.
  4. Save the entry.
  5. Select the new GMSPACS entry and press Verify / Ping / Echo. It should report success.
  6. Optional: ask the technologist to set GMSPACS as an auto-send / auto-transfer destination after each exam, so studies are sent without a manual push.
  7. Send one study manually: in the patient browser, select a study, choose Send / Push, and pick GMSPACS.
  8. Confirm it arrives: it appears in Orthanc Explorer (localhost:8042) immediately, and in the PACSD Worklist within 10 to 20 seconds.

Finding the CT's AE title if nobody knows it

Send one study from the CT. In Orthanc Explorer, open the study, click an instance, and look at the RemoteAET metadata. Or open:

http://localhost:8042/instances/<instance-id>/metadata/RemoteAET

That value is the CT's AE title.

You don't need to add the CT inside Orthanc's configuration. Orthanc accepts images from any scanner by default, so registering the CT in PACSD (Part H) is enough.

Part H: Register the CT in PACSD (DICOM Nodes)

  1. Sign in to https://pacsd.onrender.com as the administrator.
  2. In the Facility picker at the top, select the hospital (for example GH).
  3. Open DICOM Nodes and click Add.
  4. Fill in the form and save:
    FieldValue
    Node nameGE CT – GH
    AE titleThe CT's own AE title from Part G step 2, for example GECT_GH1
    HostThe CT's IP address on the hospital network (from the GE network screen)
    PortThe CT's DICOM port (often 4006 or 104 on GE; leave 4242 if unknown)
    ModalityCT
  5. Studies from that AE title now go to that hospital automatically. Repeat for every scanner (MR, X-ray, US and so on).
  6. Under Users and Roles, add the radiologists to this facility so they can be assigned studies from the Worklist.
If you skip this step, PACSD auto-creates the node under the default facility. That's fine with one hospital, but every scanner must be registered under its own hospital once there are more. AE titles must also be unique across hospitals.

If something goes wrong

ProblemLikely cause and fix
localhost:8042 doesn't openThe Orthanc service isn't running, or there's a typo in orthanc.json (a missing comma). Check services.msc.
/system shows AE title ORTHANCThe orthanc.json edit wasn't saved (open Notepad as Administrator) or the service wasn't restarted.
The Tailscale address doesn't open from your phoneFunnel isn't approved, or HTTPS isn't enabled in the admin console. Run tailscale funnel status.
Render log shows "Orthanc rejected the archive credentials"The username or password in Render doesn't match orthanc.json.
Render log shows "Orthanc is unavailable"The PC is off or asleep, Tailscale is stopped, or ORTHANC_URL is wrong.
Images are in Orthanc but not in PACSDNo facility exists. Create one; already-sent studies are picked up on the next check.
The scanner's Echo failsWindows firewall (Part B step 6), a wrong IP or port, a mismatched AE title, or the scanner is on a different network/VLAN. Ask IT to allow TCP 4242 from the CT to the Orthanc PC.
Echo works but the send failsCheck the Orthanc log (C:\Program Files\Orthanc Server\Logs) and that the PC's disk is not full.
Studies land in the wrong hospitalThe CT's AE title is not registered in DICOM Nodes under the correct facility (Part H).

Two reminders

  • The free Render plan sleeps after 15 minutes. While it sleeps it doesn't fetch new images. They wait safely in Orthanc and are imported when someone opens PACSD. On a paid plan it fetches continuously.
  • Add a Render Disk before real use (DICOM_DIR=/var/data/dicom). Otherwise PACSD's copy of the images is lost on restart. The originals stay in Orthanc, but the viewer needs PACSD's copy.

When you reach Part D, send the Render log lines after the redeploy so the connection can be confirmed.
